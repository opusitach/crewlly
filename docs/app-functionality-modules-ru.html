2. Детализация модулей

Модуль 1. Идентификация и доступ

  • Session-based авторизация: регистрация, логин, logout, профиль /api/auth/*.
  • Выбор базового режима пользователя: owner/worker /api/user/role.
  • RBAC: системные роли owner, manager, worker + матрица прав.
  • Ключевое поведение: owner/manager имеют расширенные права на смены, команду, кассу, payroll и отчёты.

Модуль 2. Онбординг

  • Owner onboarding: создание организации, таймзона/валюта, локация и часы, позиции, завершение активации.
  • Worker onboarding: проверка invite-code, присоединение к организации, выбор должностей.
  • Поддержаны пошаговые API: /api/onboarding/owner/start, /step/[step], /finish, /api/onboarding/employee.

Модуль 3. Организации и локации

  • Поддержка нескольких заведений у пользователя (через membership).
  • Переключение активной организации /api/venues/select.
  • Управление локациями и реквизитами организации: /api/locations, /api/organizations, legacy /api/venues.
  • Для каждой локации автоматически заводится касса Main.

Модуль 4. Команда и должности

  • Сотрудники: создание, поиск, профили, назначение локаций и должностей /api/employees.
  • Должности: CRUD, soft-delete, сортировка, привязка к локации /api/positions.
  • Оплата сотрудника через pay-components: hourly, fixed_shift, percent_revenue.
  • Инвайты: email-invitation и invite-code (/api/invitations, /api/invite-codes).

Модуль 5. Планирование смен

  • Workday (контейнер дня): создание и публикация /api/workdays, /api/workdays/[id]/publish.
  • WorkInterval (смена сотрудника): CRUD + pay snapshot + связи с сотрудником/позицией /api/intervals.
  • Поддержка ночных смен (переход через полночь) при вводе времени HH:mm.
  • Конфликты интервалов: обнаружение пересечений и статусы conflict.

Модуль 6. Процедуры смены (Ruleset)

  • Шаблоны правил по должности и дню недели: OPEN/CLOSE + типы CHECKLIST/INPUT/PHOTO/CASH.
  • API правил: /api/positions/[id]/rules*, ruleset preview /api/positions/[id]/ruleset.
  • При старте/закрытии смены создаются снапшоты правил для конкретного интервала.
  • Валидация обязательных пунктов и кассовых фото перед завершением этапа.

Модуль 7. Исполнение смены

  • Открытие смены: /api/work-intervals/[id]/open (с проверкой OPEN-процедур).
  • Закрытие смены: /api/work-intervals/[id]/close (проверка CLOSE-процедур + payroll snapshot).
  • Отмена запланированной смены: /api/work-intervals/[id]/cancel с обязательной причиной.
  • Owner force-open/force-close разрешены только владельцу и требуют reason.
  • Clock-in/out: /api/clock (фото/координаты/временные метки).

Модуль 8. Касса

  • Конфиг кассы на уровне локации: поля открытия/закрытия + формулы расчётов /api/cash/settings.
  • Ограничения: уникальные keys, один источник чаевых, один источник выручки, проверка формул.
  • Сессии кассы: open/close/review/get/list /api/cash/sessions*.
  • Owner-edit закрытых/проверенных сессий с audit trail и возвратом reviewed → closed при правке.
  • Чеки/вложения по сессии: /api/cash/sessions/[id]/receipts.
  • Оптимистичная блокировка изменений через lockVersion.

Модуль 9. Чаевые и выручка

  • Глобальный метод деления чаевых: equal или by_hours (/api/tips/settings).
  • Синхронизация чаевых и выручки из кассовых данных в draft-днях.
  • Использование выручки как базы для компонента оплаты percent_revenue.

Модуль 10. Отчётность

  • Сводка кассы: агрегаты по полям и формулам + предупреждения по формулам /api/reports/cash-summary.
  • Детальные отчёты: по конкретному полю кассы /api/reports/cash-fields/[fieldKey] и по формуле /api/reports/cash-formulas/[resultKey].
  • Earnings по сотруднику/воркеру: зарплата, чаевые, минуты, история начислений.

Модуль 11. Payroll

  • Создание payroll run за период с агрегацией завершённых интервалов /api/payroll/runs.
  • Payroll items: минуты, gross, tips, total payout /api/payroll/items.
  • Если расчёты интервала не зафиксированы, выполняется автопересчёт snapshot на лету.

Модуль 12. Проверка и публикация

  • Очередь проверки: завершённые смены в непубликованных днях + закрытые кассовые сессии.
  • Сводка очереди: /api/verifications/summary.
  • Публикация workday переводит день в published и закрывает редактирование кассы.

Модуль 13. Уведомления

  • Уведомления типов shift, cash, receipt, system.
  • API: список/фильтры, mark all read, mark one read, delete /api/notifications*.
  • Событийные уведомления создаются при открытии/закрытии/отмене смен и кассовых операциях.

Модуль 14. Сервисные и инфраструктурные функции

  • Фото процедур: presigned upload URL (/api/procedures/presign) + хранение ключей в БД.
  • Ретеншн медиа (cron endpoint): удаление устаревших фото процедур и маркировка photoDeletedAt.
  • Клиентский key-value state: /api/state/[key].

3. Единые статусы и бизнес-ограничения

Смены (work_intervals)
  • scheduledin_progresscompletedcanceledconflict
  • Отмена допускается только из scheduled.
  • Открытие/закрытие через force — только owner.
Рабочий день (workdays)
  • draftpublished
  • После публикации кассовые значения не редактируются.
Кассовая сессия
  • openclosing_draftclosedreviewed
  • Owner-edit доступен только для closed/reviewed.
  • Действия защищены lockVersion.
Оплата и деньги
  • Деньги хранятся в центах, проценты в basis points.
  • Pay-components поддерживают комбинированную модель начислений.
  • Percent revenue зависит от наличия базы выручки.
